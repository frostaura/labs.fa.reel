# fa.reel — Reel

## Research question
Can a per-user, content-based classic-ML recommender trained on one user's full Trakt history beat a popularity baseline by ≥20% relative precision@10 on a time-split holdout of that user's own ratings — and can that engine carry a commercial multi-tenant SaaS? Where each half currently stands, and what the eval ledger can and cannot resolve, is [`MEMORY.md`](MEMORY.md)'s business, not this file's.

## What this program is
A multi-tenant movies/TV recommender SaaS built on Trakt. A user links their Trakt profile; Reel ingests everything ever watched plus ratings and in-progress shows, derives LLM tone/pacing/theme attributes and plot embeddings, and trains a **per-user** ML.NET FastTree model that predicts that user's 0–10 rating over an explicitly versioned feature vector (the width lives in `FeatureSchema.cs` and is never typed into prose — it has already been wrong twice). It serves an explainable feed restricted to titles the user has not finished, with live search and where-to-watch provider strips, and writes back to a managed Trakt list ("Reel — Up Next") that syndicates into Plex/Kodi/Infuse. Interesting now because LLM feature extraction makes content-based recommendation viable for a single user from day one — no cross-user data needed at launch.

## Stack & repo
`github.com/frostaura/fa.reel` (**private** — see the stealth decision in [`MEMORY.md`](MEMORY.md); the `LICENSE` file is still MIT but the repo is not published).  Mandated stack throughout: .NET 10 with `TreatWarningsAsErrors`, EF Core + Npgsql, React 19, Tailwind, shadcn/ui, Vite, Redux Toolkit. Solution `fa.reel.slnx` at root; hexagonal backend under `src/backend` with layering enforced by project references; frontend under `src/frontend`. ML is ML.NET FastTree in-process (pure managed, arm64-safe). Embeddings and LLM calls route through OpenRouter behind `IEmbeddingProvider`. Data sources: Trakt (history, ratings, watching) and TMDB (catalogue, search, metadata, watch providers). **One documented deviation:** the database image is `pgvector/pgvector:pg16` rather than the house `postgres:16-alpine`, because vector and trigram extensions must be compiled in — justified in a compose comment. Standard FrostAura deploy pattern targeting `reel.frostaura.net`. **Quality bar: Silver.**

## Milestones
1. **App skeleton** — Trakt OAuth wireup, background sync into Postgres, tenant model, verified founder ingest.
2. **In-app ML pipeline + edge proof** — feature extraction, training and time-split evaluation running as app jobs, beating the popularity baseline by ≥20% relative precision@10 on a leakage-clean split.
3. **MVP surface** — per `docs/product-spec.md`: picks hero and rows, card anatomy and expanded modal, reactions plus Trakt write-back to the managed list, both search modes, where-to-watch ladder, taste-DNA dashboard, onboarding reveal.
4. **Multi-tenant** — row-level isolation audited on real Postgres, entitlements enforced server-side, shared rate budget, and **≥5 external users**.
5. **Commercial gate** — Trakt commercial-API terms agreed; JustWatch deep-link decision made.

## Kill criteria
- The model cannot beat the popularity baseline by a meaningful margin after **3** modelling iterations.
- Trakt refuses commercial use, or prices it beyond the unit economics.
- **Fewer than 5 external users willing to link a profile within 60 days of MVP.**

## Graduation pathway
`Technologies/` once the recurring-revenue path is proven — the standard Labs → Technologies graduation pattern. `Ventures/` only on standalone-brand traction. If Trakt refuses commercial use, kill the product but keep the engine: the per-user feature/training/eval machinery is reusable elsewhere.

## Conventions & invariants
- **No manual pipelines (founder-locked).** OAuth wireup, ingestion, feature extraction, training and evaluation all run inside the app, driven by per-user config. Ad-hoc scripts and notebooks are never the path of record.
- **Eligibility rule (founder-locked): "never show things I've already seen."** Suggestion surfaces — feed hero and rows, Ask Reel, lexical and semantic search — show only titles with a **zero interaction footprint**: no watch history even partial, no rating (a rating implies it was seen, including titles rated without a logged play), not marked NotInterested. In-progress titles appear exclusively on the continue-watching surface. Enforced in `EligibilityQueryBuilder.EligibleTitles`. Typeahead intentionally still finds watched titles — that is lookup, not suggestion — badged via `ContentFilteredTitles`.
- **Identity is Sign in with Trakt only (founder-locked).** The OAuth callback *is* account creation; the app session is `reel_at`/`reel_rt` HttpOnly cookies. Row-level tenancy runs through `IAccountScoped` plus EF global query filters, and **a model test fails the build if a scoped entity ships without isolation.**
- **An Ask Reel turn is a server-owned record.** The server persists the question, the answer's cards (tray rows included), the resolved intent, the conflict, the reason and the stage timings; the client sends `{ query, conversationId?, clientTurnId, mediaTypes?, pageOf? }` and nothing else — history and the no-repeat set are derived from the record, never trusted from the client. A replayed card is re-filtered through eligibility on read and writes no exposure. Contract, lifecycle and refusal codes: [`docs/ask-reel-turns.md`](docs/ask-reel-turns.md).
- **A standing exclusion is airtight on every channel, and only the user's own words are negations.** The "outside your request" channel may relax a negation the user typed, never a `ContentFilter`; a negation counts only when its object resolves to a genre or a vocabulary keyword (`Application/Search/SearchVocabulary.cs`); the model's inferred exclusions steer discovery and never caption a card.
- **A cache in front of an LLM call is keyed on every input the prompt reads.** The interpretation key carries the account, the question, the standing-filter summary, the media filter, the model, the prompt version and digests of the transcript and the shown set (length-prefixed, invariant; "no history" is its own key) — a key that omits an input serves one conversation's answer to another. `Application/Search/LiveSearchExpansionService.InterpretKey` is the reference shape.
- **An in-flight `SearchTurn` is never trusted past three minutes, and boot closes what a dead process left.** `PendingTurnReconciliation` runs before `app.Run()` (a hosted service would start after the listener) and marks every Pending row `Failed`/`server_restarted`; the `/ask` gate, the idempotent replay and `GET /turns/{id}` close a stale Pending as `turn_timed_out` and let the retry proceed. Any new "in flight" row needs both mechanisms, because only the request pipeline can otherwise close it.
- **Every user-facing LLM completion sets `max_tokens` and treats `finish_reason == "length"` as failure.** The search agent's ceilings are 400 (interpret) and 900 (rerank); a rerank batch past ~11 titles starts silently degrading to stub fits.
- **DB-backed tests live under `Tests/IntegrationTests/`** — CI's integration job filters on that name and the unit job has no database, so a test elsewhere reports green having run nothing. HTTP-level tests use `IntegrationTests/ReelApiFactory.cs`, never a bare `WebApplicationFactory`.
- **`FeatureSchema.cs` is explicitly versioned, and version numbers are never recycled.** Changing feature order is a schema version bump, never an in-place edit — stored artifacts would otherwise silently misread their own inputs. **A bump that is reverted burns its number:** the version history in that file is append-only *including reverts*, the reverted entry keeps the measurements that killed it, and the next bump takes the next integer rather than the freed one — otherwise two different vectors answer to one integer in stored `ModelArtifact.FeatureSchemaJson` rows, which is exactly the silent misread the versioning exists to prevent. Reverting a bump also does **not** restore the previous artifact: superseding is a one-way status write, so the account is left with no `Active` artifact and `NightlyReconcileService` retrains it on the next boot. That is the designed degradation, not a defect.
- **`TitleScore` is never read by training or evaluation code.** It is not write-only in general — the serving path reads it (`OnDemandScorer`, the calibration fit in `RatingCalibrationService`, the retro loop). Its doc-comment says exactly that and states no leakage guard, so the guard is this rule plus the absence of any read in `EvalHarness.cs` and `FeatureVectorBuilder.cs`; the entity that does carry its own leakage guarantee in its doc-comment is `PersonAffinity`, and that is the pattern worth copying.
- **The eval harness is deliberately hostile to itself** (`EvalHarness.cs`): five rolling split origins (60/65/70/75/80%) on the immutable `UserRating.FirstRatedAt`, reported per-origin and as a mean — 80% is only the *primary* origin, the one whose numbers land in the ledger columns so earlier iterations stay comparable; holdout triple-filtered to newest, not-in-train, and not in `WatchedTitles` before the split; features built strictly as-of `splitAt`; positive threshold `max(8, trainMedian)` — "loved, not tolerated"; a symmetric popularity baseline over the identical pool; and a two-clause gate that reads **NDCG@10, not precision@10** — the bootstrap CI on the paired model-minus-baseline NDCG lift must exclude zero in the model's favour **and** the mean relative NDCG lift across the five origins must clear 20% (`NdcgLiftGateThreshold`). precision@10 is retained and persisted as a **display** metric only: it is quantised to 0.1 on a top-10 cut, so its achievable lift lattice moves with the baseline, and `LegacyGatePassed` exists solely to keep the historical ledger rows comparable. It **persists its own caveat** that the popularity baseline uses present-day TMDB popularity because no historical snapshots exist. **That caveat must never claim the effect is symmetric between model and baseline — it is not.** Present-day popularity is 100% of the baseline's ranking signal and one feature among many in the model's, so the asymmetry runs *against* the model and the measured lift is understated, not flattered. The caveat interpolates `FeatureSchema.VectorLength` rather than repeating a number. Do not soften any of this to make a number look better.
- **The calibrator is applied LAST, on every displayed prediction, and never inside training or evaluation.** A monotone `RatingCalibrator` sits after the base score and the residual head wherever a rating reaches a user (`OnDemandScorer`, feed build, paginator, saved backfill). Its mode is `CALIBRATOR_MODE`, and it falls back to a bias shift when the pairs carry no rank signal — an isotonic fit on ρ≈0 pairs maps everything to one number, which is honest and useless. The residual head exists for discriminative corrections only; **never normalise its bias away without a replacement calibrator in place.**
- **`UserRating.FirstRatedAt` is immutable and is the split axis.** It exists because ~2,000 historical ratings share one ingest timestamp, so any `ObservedAt`-style column collapses the holdout to zero and the ledger stops silently. It is written once and never recomputed, and it is also the retrain-gate axis.
- **The exposure log is append-only.** `ExposureEvent` rows are written where cards are actually served — feed build, `/feed/more`, rails, digest, Ask Reel, push and the live refill in `FeedEndpoints` — idempotent per `(AccountId, TitleId, Surface, FeedSnapshotId, MinuteBucket, SourceTurnId)` with `AreNullsDistinct(false)`, and are never updated or back-filled. **`SourceTurnId` is the last member and is not optional** — without it the key collapses to (account, title, minute) on every Ask Reel row, where `FeedSnapshotId` is null by definition, so two turns in one minute recommending the same title write one row stamped with the wrong turn. Everything derived (`ExposureOutcomes`, `TitleExposureRollups`, `UserRatingEvents`) reads from them. Attribution is a temporal join, because only ~2% of ratings are made in-app. No client viewport beacon.
- **Lens copy is guarded, and the guards are not decoration.** Generated notes must anchor only on titles the account has rated, watched or reacted to (matched by normalised name); invented anchors are stripped rather than treated as fatal; `SoundsAntiRecommendation` is applied to the note but deliberately **not** to `caution`; spend is capped per account per day by `LLM_LENS_DAILY_CALLS` / `LLM_LENS_DAILY_TOKENS` on the token ledger, with a three-rung fallback (stale note → templater → overview). No prompt version reaches anyone but the founder until 50 generations have been human-reviewed via `GET /api/dev/lens-audit`.
- **Where-to-watch:** TMDB watch-provider data is legal, but deep links are licence-restricted by JustWatch. Ship provider badges and provider-side search links; true deep links require a partnership. **No scraping.**
- **Every number this backend formats is invariant, without exception.** Nothing here is localised: prompts, TMDB/Trakt query strings, cache keys, stored `ContentFilter.Value` rows, SSE payloads, persisted insight text and job progress messages are all machine-read or compared as exact strings, so a comma decimal separator is a wrong answer rather than a different rendering — and a silent one, because TMDB *ignores* a malformed parameter and returns a valid, unfiltered page. Three things hold the line together and all three are load-bearing: `Program.cs` pins `CultureInfo.DefaultThreadCurrentCulture` at host start (the test assembly does the same in a module initializer); every formatting site states the contract itself with `string.Create(CultureInfo.InvariantCulture, $"…")` / `FormattableString.Invariant`; and `Tests/Harness/CultureSensitiveFormattingGuardTests.cs` greps the backend sources for the shapes CA1305 cannot see (`$"{x:F3}"` and friends) with a *reasoned* allowlist. Structured-logging templates are exempt — `FormattedLogValues` is already invariant. Dates in outbound URLs count: `ar-SA` defaults to Umm al-Qura, so an unqualified `yyyy-MM-dd` writes a Hijri year.
- The extraction model is founder-locked to `openai/gpt-5.4-mini`.
- nginx config has **three descriptors**: `nginx/nginx.conf` is the canonical file, mounted by the dev compose stack; `docker-compose.prod.yml` and `deploy/portainer-stack.yml` inline copies of it as a compose `configs:` block for a stated reason — Portainer stacks cannot mount repo files. **Two prefixes stream, not one.** `/sse/` — the pipeline/onboarding channel — is proxied with buffering off and `proxy_read_timeout 86400s`; `/api/` carries the same six directives at `3600s`, because Ask Reel's turn streams on `/api/search/ask` and a buffered turn arrives as one lump that reads as a slow model. `Tests/Harness/NginxDescriptorParityTests.cs` pins the two inline copies to the canonical file, not against a directive being removed from all three.

## Build / test / run
**Work in the dev clone, not in iCloud.** The repository is cloned at `~/src/fa.reel` and that is where building, testing and the dev loop happen — Vite on **5173**, the API on 5054 under plain `dotnet run` (restarted by hand after a merge — **never `dotnet watch`**, whose hot-reload prompt and restart port race both leave a stale binary serving; recipe in [`MEMORY.md`](MEMORY.md)), Postgres in Docker on 5433. The copy under `FrostAura Global/Labs/projects/fa.reel` is the context-file home only; building there is slow enough to hang the toolchain (see [`MEMORY.md`](MEMORY.md)).

Local Postgres publishes on **5433**, not 5432 (5432 is taken on the dev Mac). CI runs `dotnet format` as a gate, dual coverage ratchets (backend 10%, frontend 6% — honestly labelled a regression guard, not a target), `npm audit --audit-level=high` and `dotnet list package --vulnerable` as build-failing security gates, a real `pgvector/pgvector:pg16` integration service, and **native `ubuntu-24.04-arm`** builds rather than QEMU.

**Deploy — see [`docs/deployment.md`](docs/deployment.md).** Every push to `main` publishes multi-arch `reel-backend`/`reel-frontend` `:latest` to Docker Hub. CI's `Docker Build & Stack Smoke` job (`make docker-ready`) gates those publish jobs and runs on PRs too, so broken Dockerfile or compose wiring can no longer reach a `:latest` push. The Portainer redeploy is gated by the `DEPLOY_ENABLED` repo *variable* so it skips rather than fails while the stack is missing; whether it is set is state, and lives in [`MEMORY.md`](MEMORY.md). `make` is the shared entrypoint for CI and local alike. CI has no scheduled trigger — push, PR and manual dispatch only.

**Integration tests are opt-in locally and mandatory in CI.** `REEL_TEST_CONNECTION_STRING` must point at a **throwaway** database — the fixture drops and re-migrates it every run, so never aim it at `reel`. With the variable absent the integration tests skip silently and a plain `dotnet test` stays green; CI sets **`REEL_REQUIRE_INTEGRATION=1`**, which converts that silence into a hard failure, because a suite reporting green having run nothing is worse than a red one. Integration tests that are known local-only failures may be quarantined via `[LocalFlakyFact]` + `[Trait("Flaky", "local")]`, and `Tests/Harness/LocalFlakyQuarantineTests.cs` pins that set by name so it can only change deliberately; **`REEL_SKIP_LOCAL_FLAKY=1` belongs in the local command only and must never be set in CI** — CI's pgvector service is authoritative and runs all of them. A row leaves the quarantine only when the underlying defect is fixed, never by relaxing the assertion — and every row that ever left turned out to be a real defect in a fixture or a superseded assertion, never an environment difference, so treat "it only fails locally" as a hypothesis to disprove rather than a diagnosis. What the set holds right now is [`MEMORY.md`](MEMORY.md)'s business, not this file's. The recommended local invocation is in [`README.md`](README.md).

**Playwright will silently drive the LIVE app.** `playwright.config.ts` sets `reuseExistingServer: !isCI` on 5173, which the dev Vite owns, so a bare `npx playwright test` runs against whatever is already serving. Always run **`CI=1 PW_PORT=<free port> npx playwright test`**.

**Runtime flags worth knowing before changing behaviour:** `CALIBRATOR_MODE` (calibrator policy), `RESIDUAL_HEAD_ENABLED` and `RESIDUAL_OBSERVE_TRAKT_RATINGS` (the online residual head, and whether Trakt-synced ratings feed it), `INTERLEAVE_ENABLED` with `INTERLEAVE_POLICY_A`/`_B` (team-draft interleaving on Fresh builds), `LLM_LENS_DAILY_CALLS` / `LLM_LENS_DAILY_TOKENS` (per-account lens ceilings), `LLM_XREF_DAILY_CALLS` / `LLM_XREF_DAILY_TOKENS` (the cross-reference verdict job's per-account ceilings; zero is the off switch) and `LLM_RERANK_DAILY_CALLS` / `LLM_RERANK_DAILY_TOKENS` (the rerank family, background builds stop at 70%), `KILL_CRITERION_ITERATIONS` (what the ledger surface calls the criterion), `ENRICH_MAX_TITLES_PER_RUN` (enrichment sweep cap), and the catalogue-supply set — `SEED_MOVIE_MIN_VOTES` / `SEED_SHOW_MIN_VOTES` (which decide how big the bulk-seeded corpus IS), `SEED_PAGES_PER_RUN` / `SEED_MAX_TITLES` (per-run and overall seed budgets), `HYDRATE_MAX_TITLES_PER_DAY`, `EXTRACT_DAILY_TOKENS` and `EMBED_DAILY_TOKENS` (the system-wide daily ceilings that pace completing it). Their current settings are state and live in [`MEMORY.md`](MEMORY.md).

**Catalogue supply is a separate concern from ranking, and it is enforced with ceilings rather than trust.** The bulk seed (`JobKind.SeedCatalog`, founder-only `POST`/`GET /api/dev/seed-catalog`; like every `/api/dev` route it is mapped only under `Development` plus `QA_HELPERS_ENABLED` — `DevEndpoints.MapDevEndpoints` returns before mapping anything otherwise, so a `Production` stack has no seed trigger) walks TMDB discover partitioned by release year — TMDB caps discover at page 500, so an unpartitioned query cannot reach the tail no matter how patiently it is paged — writing summary rows only. Completing those rows is deliberately a different job on a different budget: hydration is bounded in TITLES because TMDB is free within the rate gate, enrichment in TOKENS against the `ExternalApiUsages` ledger, and both ceilings are **system-wide, not per-account**, because a `Title` row is shared by every tenant — a per-account gate would admit N accounts' worth of spend against a budget written for one. Every catalogue-wide ceiling added here must keep that property, and must be re-checked per batch rather than once per run: a run that starts inside its budget can spend past it inside a single 15-second ledger window.

**Dev QA helper:** `POST /api/auth/dev/link` (Development plus `QA_HELPERS_ENABLED=true` only) links `TRAKT_DEV_PROFILE` using `TRAKT_ACCESS_TOKEN`/`REFRESH_TOKEN` from `.env`, giving the full pipeline and a session without the browser consent hop. The production path of record remains the OAuth callback.

**External accounts required:** Trakt (identity, history, write-back), TMDB v4, OpenRouter (LLM plus embeddings), Docker Hub, Portainer, Cloudflare. Stripe optional.

**Footguns, already paid for:** Trakt and TMDB sit behind Cloudflare, which 403s UA-less requests — the explicit User-Agent on the typed clients is load-bearing. All `DateTime`s normalize through a model-wide UTC converter, because Trakt's date-only fields arrive `Kind=Unspecified` and Npgsql refuses them.

## Never do this here
- Never surface a title with any interaction footprint on a suggestion surface.
- Never edit `FeatureSchema.cs` field order in place, and never re-use a schema version number that a reverted bump already spent.
- Never read `TitleScore` from training or evaluation code.
- Never assume a filtered vector query's `WHERE` bounds what pgvector returns — an HNSW scan post-filters a fixed candidate window and stops, so `hnsw.iterative_scan` (issued per connection by `HnswFilteredSearchInterceptor`, which `ReelDbContext.OnConfiguring` registers) is what makes the pull whole, and a test that seeds `TitleEmbeddings` must inherit `EmbeddedCatalogTestBase`.
- Never introduce a manual/notebook pipeline as the path of record.
- Never scrape watch-provider deep links.
- Never format a number or a date into a prompt, URL, cache key, filter row or SSE payload without `CultureInfo.InvariantCulture`.
- Never update, delete or back-fill an `ExposureEvent`, and never mutate `FirstRatedAt`.
- Never apply the calibrator inside training or evaluation, and never remove the residual bias without a calibrator in its place.
- Never point `REEL_TEST_CONNECTION_STRING` at `reel` — the fixture drops the database it is given.
- Never run Playwright without `CI=1` and a free `PW_PORT`; it will otherwise test the founder's live stack.
- Never run the API under `dotnet watch`, and never start the API from a worktree — the first serves a stale binary, the second migrates the live database under a branch's migration id.
- Never let a model opinion (an LLM verdict, a fit score) into `EligibilityQueryBuilder` — it holds user statements only; opinions demote in the ranking layer where the closed loop can see them.
- Never ship an `IAccountScoped` entity without its global query filter — the build should catch you, but do not rely on that.
- Never trust a client-supplied transcript or no-repeat list on `/ask`, and never infer a page from the last user turn — the record and `pageOf` are the only sources.
- Never create a mount guard inside a React effect body — StrictMode runs the effect twice and the first guard's abort cancels the page's own request; hold one per hook instance and name every deliberate abort.

## Upkeep

This file, `MEMORY.md`, its `memory/` topic store, and the skills that fire at this level are kept current **as changes land**, not in a later cleanup pass. `MEMORY.md` is required here exactly as this file is, and it cascades downward on identical terms — an instruction file with no `MEMORY.md` beside it is a defect, not a shortcut: the rules are stated and reality is left unstated, so the next agent infers status instead of reading it. Both files, or neither.

- **Memory — always.** Update the topic files at the end of any session that shipped, decided, discovered, abandoned or unblocked something; re-cut the `description:` of any topic whose signal moved, then regenerate `MEMORY.md` from the topic files rather than editing it — `python3 .claude/scripts/audit-tree.py --no-git --fix-index --scope Labs/projects/fa.reel` from the tree root; restamp `last_verified:` only for what you actually re-inspected. Record decisions *with their why* — a decision without its rationale is reversed by the next agent, who sees only its cost.
- **This file — only when a rule changed.** A new convention, command or invariant earns an edit. A status change does not; it belongs in the memory store.
- **Skills — when *how* the work is done changed.** Fix or delete a skill whose commands or thresholds no longer exist; a stale skill is worse than a missing one because it fires with authority. A procedure that would be correct in a repository with nothing to do with this tree belongs upstream in a plugin, never forked into this tree.
- **Scratch — always.** Empty `.tmp/` before the session ends, promoting anything that still mattered first.

None of these four are assessed by search. Read the scope's files end to end before changing any of them. Drift is not caused by neglect over months; it is caused by good sessions that ended without a close-out.
