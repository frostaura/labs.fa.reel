# Live decisions

- **The repo is PRIVATE as of 2026-08-07 (founder). The stealth exception is reversed, not recorded.** `frostaura/fa.reel` had been public while Labs is stealth-by-default, and the exception had never been written down — an open question since 2026-07-24, flagged as needing a founder call *before* the first push in over a month. Asked and answered at the point of that push: flip private, then push. `gh repo edit --visibility private` ran first, then 13 commits went to `origin/main` (`513bd10` → `fde7680`), closing a durability gap in which ~2 months of work existed only on the founder's Mac plus iCloud. **Consequence to remember:** the repo is no longer MIT-public in practice — the `LICENSE` file is still MIT but nothing is published — and any future decision to go public is a fresh founder call requiring a recorded exception. `CLAUDE.md`'s stack section was corrected to say so.

- **Deploy (founder, 2026-07-24).** The external-user kill criterion is evaluated against a *deployed* product, so the trip-by-timer-for-logistical-reasons scenario is void. Remaining founder steps: push, create the Portainer stack from `deploy/portainer-stack.yml`, set `DOCKERHUB_TOKEN` / `PORTAINER_*` secrets and the `DEPLOY_ENABLED` variable, point Cloudflared at `reel.frostaura.net`.
- Extraction model `openai/gpt-5.4-mini`, no manual pipelines, eligibility = zero-interaction-footprint, identity = Sign in with Trakt only — all founder-locked 2026-06-12 and carried into `CLAUDE.md`.
- **Collaborative filtering shipped** 2026-06-18 (item-based via TMDB recommendations, in `CandidateGenerator.cs`). The old "deferred to ~200+ tenants" framing is dead.
- **Stripe is scaffolded and deploy-ready**, flag-gated off with blank keys.
- **Embeddings are remote, not local** — `EMBEDDINGS_PROVIDER=openai`, `text-embedding-3-small`, **1536 dims** via OpenRouter. Local ONNX MiniLM at 384d is no longer the default.
- **The npm audit gate now allows narrow, EXPIRING waivers — and one is active (2026-08-07).** `npm audit --audit-level=high` was replaced by `src/frontend/scripts/audit-gate.mjs` (`npm run audit:gate`), which is identical except that a named advisory can be waived with a reason and a review date, and the gate **fails** once that date passes. This exists because react-router has no clean version: the open-redirect advisory (GHSA-wrjc-x8rr-h8h6) covers 6.0.0–7.17.0 while GHSA-qwww-vcr4-c8h2 covers 7.12.0–8.2.0, and no 8.x is published — every version carries one or the other. Reel is a client-only SPA with no RSC entry point, so the RSC-mode CSRF path is unreachable while the open redirect is not; **7.18.2 is the better posture, not the more convenient one**, and GHSA-qwww-vcr4-c8h2 is waived until **2026-11-07**. Verified the gate still fails on an un-waived high and on an expired waiver, so it is not vacuous. **Waiving an advisory is a cybersecurity decision, which root `CLAUDE.md` places at parent level — this one needs founder review at the expiry, not a silent renewal.**
- **Vulnerable transitives get an explicit pin, not a suppression.** Two now: `Microsoft.OpenApi` 2.7.5 (GHSA-v5pm-xwqc-g5wc via AspNetCore.OpenApi 10.0.9) and `System.Security.Cryptography.Xml` 10.0.10 (GHSA-8q5v-6pqq-x66h et al. via DataProtection.EntityFrameworkCore 10.0.9). Both carry a comment saying to remove them once upstream ships a patched transitive. The `security` CI job fails the build otherwise.
- **2026-08-10 — Trakt history writeback is movie-only** (`4095762`). *Why:* the spec mandates watched-status writeback, but a bare show object on Trakt `sync/history` marks every aired episode watched — rating a show from memory wrote ~801 fake plays to the founder's real history. Scoping to movies keeps the spec honored where the semantics are safe; shows sync ratings only. `RemoveFromHistory` (anchored on `WatchedTitle.ReelLoggedWatchedAt`) makes the movie path reversible.
- **2026-08-10 — Stable-tonight contract** (`0db6625`). *Why:* two contradictory founder complaints (2026-08-07: "rows never change"; 2026-08-07 QA: "hero churned 3×/hour") resolve as: identical within a UTC day (Preserve mode + no-op snapshot suppression), guaranteed different across days (day-seeded AnchorRotation), immediate change on user action (reaction vacates its slot; manual refresh / filter change / retrain force Fresh). Do not re-tune one side without re-checking the other.
- **2026-08-10 — Negations quarantine, never mix** (`79d8c60`, `06016fc`). *Why:* the reserve top-up used to refill to ReturnCount unflagged, so "no horror" showed 7 horror cards whose LLM captions admitted the violation. Contradicting titles now only ever appear under the labeled "Outside your request" channel (≤ the MinResults floor) with deterministic captions — and genre exclusions match Subgenres/Keywords because TMDB's TV taxonomy has no horror genre.
- **2026-08-10 — Dislike reasons demote by similarity, not just exclusion** (`0d207cf`). *Why:* founder: "the dislikes and their reasons I give must be taken into account." Reactions previously only hid the one title. Reason-weighted demotion (genre/tone/seen-enough/centroid, capped 1.5 rating points, 180-day recency-decayed) applies at OnDemandScorer, feed build and pagination; residual model observes dislikes as weak pseudo-ratings; FeatureSchema v3 adds simNotInterestedCentroid/dislikedGenreOverlap — the version bump deliberately forces per-account retrain on deploy.
- **2026-08-10 — Why-lines are anchored, specific and never self-defeating** (`94f9a8d`, `7232884`). *Why:* founder: rail captions like "Because you loved Hokum, and peak 2000s" ×5 verbatim are "way too basic and vague". LLM whys are persisted at build time with anchor context; "Because you loved" openers and anti-recommendation phrasings are rejected by construction (guard + hero fit-floor swap); templater fallback is sentence-cased, variant-hashed, generic sentence at most once per response.
- **2026-08-10 — PIN unlock is a DataProtection token, never the cached raw PIN** (`991e013`). *Why:* the client stored the plaintext PIN in sessionStorage and replayed it per call — any XSS or shared-screen devtools read it. verify → 15-min `X-Settings-Unlock` token; destructive ops always re-prompt for the raw PIN.
- **2026-08-10 — Lookup ≠ suggestion extends to TMDB** (`d3ea403`). *Why:* typeahead's catalogue scope made any un-ingested film unfindable. Global TMDB rows (flagged, unscored) + on-demand hydration keep the zero-footprint suggestion invariant intact while making all of TMDB addressable.
- **2026-08-10 — Digest/Push/Blend shipped behind existing patterns** (`c5483f5`). *Why:* wishlist items; Web Push uses self-generated VAPID (no third-party service), blend uses `IgnoreQueryFilters` strictly for exclusion-only intersection (no cross-tenant data surfaced), PWA switched generateSW → injectManifest to host the push handler.

- **2026-09-10 — every number the backend formats is INVARIANT, and a source-level guard enforces it** (branch `hygiene/culture-affinity`). *Why:* nothing here is localised — prompts, TMDB/Trakt query strings, cache keys, stored `ContentFilter.Value` rows, SSE payloads and job progress messages are machine-read or compared as exact strings, so a comma decimal separator is a wrong answer, not a rendering choice, and TMDB *ignores* a malformed parameter rather than rejecting it. Three defences, all load-bearing: `Program.cs` pins `CultureInfo.DefaultThreadCurrentCulture` (test assembly does the same in a module initializer); each site states the contract with `string.Create(CultureInfo.InvariantCulture, …)`; `CultureSensitiveFormattingGuardTests` greps the sources for the shapes **CA1305 cannot see** (`$"{x:F3}"`) with a reasoned allowlist. Sites found and fixed included the three TMDB discover **date** bounds — under `ar-SA` an unqualified `yyyy-MM-dd` writes a Hijri year and silently fetches the wrong two decades. **`Convert.ToDecimal`/`ToInt32` in `EligibilityQueryBuilder` stay provider-less on purpose:** EF translates only the single-argument overloads, and passing a provider makes the predicate untranslatable (~40 integration tests go red).
- **2026-09-10 — "it only fails locally" is a hypothesis, not a diagnosis; the quarantine is EMPTY.** *Why:* all three remaining `[LocalFlakyFact]` rows were deterministic failures everywhere, CI included. Both `LiveSearchExpansionTests` rows: the fake TMDB client returned `OriginalLanguage = null`, so discovered candidates were upserted with a null `Language` and dropped by the English-only eligibility default added in `e790bb2` — a stale fixture, not a machine. `LexicalSearchIntegrationTests.Keyword_exclusion_…`: it asserted the REVERSE (filter-contains-keyword) exclusion arm, deliberately deleted in `2767cf9` for over-excluding ("warehouse" swallowed "ware") — a superseded contract nobody updated. Every row that has ever left that quarantine turned out to be a real defect. The pin and the attribute stay, with an empty set, so adding a row remains a decision.
- **2026-09-10 — `PersonAffinities` has a writer, and it forks no maths** (`PersonAffinityWriter`). *Why:* the entity, index, tenancy filter and a reader (`CandidateGenerator.TopPeopleTmdbIdsAsync`, discovery arm 2) all shipped with no writer at all, so the table was empty on every account and the person-discover arm contributed nothing to any feed build — silently. Affinity and pool size come from `VerifiedPeople`, the same path the why-sentences read, so a stored row cannot quote a different number than the card. The pool is **role-agnostic** (`TasteState.PersonRatings` is keyed by person), so an actor-turned-director carries one average across every credit; the role says which capacity they were credited in, not which the average was measured in. Refreshed inside `TrainJobHandler`'s own save — model and supply describe one snapshot — plus a once-only nightly backfill for accounts whose table is empty. `FeatureVectorBuilder` still recomputes as-of the split point and must never read this table; that is the leakage guarantee.
- **2026-09-10 — one score resolution across `FeedItem`, `TitleScore` and the exposure log (2 dp).** *Why:* a calibration join inherits the coarsest side, so `FeedItem`'s 1 dp put a 0.05 quantisation floor under residuals of the same order as the deltas being measured. Invisible to users — the badge renders `toFixed(1)` — and no migration, the column is unconstrained `numeric`.
