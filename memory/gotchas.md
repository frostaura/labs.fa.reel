# Gotchas

## Environment and workflow
- **Develop from `~/src/fa.reel`, never from the iCloud copy.** On 2026-09-09 fileproviderd pushed load to 13 on the iCloud tree: `git status` took over 2 minutes, a 40 MB Docker context 16 minutes, Vite 137 s to boot and then it hung on a file close (the sign-in button stayed disabled while the PWA shell rendered from cache). The clone starts Vite in 330 ms. The iCloud directory is the context-file home only.
- **iCloud can delay another session's file writes by MINUTES.** During the 2026-08-10 remediation a subagent looked stalled and its files "missing", then the whole batch landed mid-way through the salvage agent's run. On this volume, absence on disk is not evidence of absence — wait and re-list before declaring another session's work lost.
- **`dotnet watch` processes from an EARLIER session survive and keep rebuilding.** Three from 2026-09-10 were still alive on 2026-09-11 evening, racing every test build for `FrostAura.Reel.Api/obj` (MSB4018 "process cannot access the file … staticwebassets"); plain `kill` did not end them, `kill -9` did. `pgrep -fl 'dotnet watch'` before any build. **Restarting the API drops the dev-link session** (the app falls to the landing page) — re-POST `/api/auth/dev/link` from the page origin and reload.
- **Never run the API under `dotnet watch`; run it with plain `dotnet run` and restart it yourself after a merge.** With hot reload on, a merge that adds an enum value or a class stops at a "Restart is needed … Yes/No/Always/Never" prompt that waits on stdin forever while the old binary keeps serving. With `--no-hot-reload`, every restart raced the previous child for port 5054 and died on "address already in use" — again with the stale binary serving, while the NEW binary had already applied its migrations before dying. Two backtests ran against the wrong build on 2026-09-11 before this was caught. Recipe: `~/.dotnet/dotnet build src/backend/FrostAura.Reel.Api && ASPNETCORE_ENVIRONMENT=Development ASPNETCORE_URLS=http://localhost:5054 nohup ~/.dotnet/dotnet run --no-build --no-launch-profile --project src/backend/FrostAura.Reel.Api < /dev/null > /tmp/apiN.log 2>&1 &`, then confirm the listener's start time postdates the merge: `ps -o lstart -p $(lsof -tnP -iTCP:5054 -sTCP:LISTEN)`.
- **A worktree's migration can reach the live DB.** `PostgresFixture` only touches `reel_test_*`, but anything that starts the API from a worktree with the repo `.env` migrates `reel` under the BRANCH's migration id; when the integrator re-scaffolds that migration on main, the live API then fails at startup trying to create tables that exist. Fix used 2026-09-10: rename the `__EFMigrationsHistory` row to main's id after verifying the DDL is byte-identical. Prevention: never run the API from a worktree; `dotnet ef migrations add` only.
- **`git branch --merged main` matches a branch created from main seconds ago.** A "remove merged, clean worktrees" sweep on 2026-09-10 deleted two agents' fresh worktrees from under them. Prune worktrees BEFORE launching agents, never alongside them.
- **A day-granular fixture built from `DateTime.UtcNow` plus an offset fails deterministically inside the 23:00 UTC hour** (01:00–02:00 SAST) and looks exactly like a timezone bug in the product. `TasteClusterRetrievalTests` cost an evening this way on 2026-09-11; the product keys every day-granular thing on UTC correctly. Pin fixture instants to fixed hours of one UTC date.
- **Integration tests DROP the database they point at.** `REEL_TEST_CONNECTION_STRING` must name a throwaway DB — `reel_test_w1..w6`, `reel_test_int`, `reel_test_base` exist on :5433 for parallel worktrees (`~/src/fa.reel-wt/<branch>`). **Never `Database=reel`.** Absent the variable, integration tests skip silently and a bare `dotnet test` stays green; `REEL_REQUIRE_INTEGRATION=1` turns that silence into a hard failure and is what CI sets.
- **Playwright silently drives the LIVE app if 5173 is busy.** `playwright.config.ts` sets `reuseExistingServer: !isCI` on 5173, which the dev Vite owns — a bare `npx playwright test` therefore runs against the founder's live stack and every new spec fails for the wrong reason. Always run `CI=1 PW_PORT=<free port> npx playwright test`.
- **`.env` holds live credentials** — Trakt client secret, TMDB token, OpenRouter key, JWT signing secret and real Trakt access/refresh tokens. Correctly gitignored; the iCloud copy is nonetheless continuously synced to Apple's cloud. Rotate before public launch.
- **`POST /api/auth/dev/link`** short-circuits to a session when the dev account already exists in the DB, without touching Trakt (verified 2026-08-07/10). **Trakt's Cloudflare blocks the Claude Code browser pane** on the authorize page (the Electron UA trips bot protection) — OAuth sign-in must happen in a normal browser; the pane works fine once a session cookie exists. **The dev-link session expires after roughly 85 minutes** (401 on `/api/auth/me`, app drops to the landing page) — re-POST it from the page origin and reload.

## Building, testing and probing (2026-09-10/11 panels and programme)
- **`ExternalApiUsages` is day-grained** — keyed `(Provider, Day, AccountId, Model, Purpose)`, no per-call rows — and **`Purpose = rerank` is written by four callers** (two in `BuildFeedJobHandler`, `FeedPaginator`, `LiveSearchExpansionService`). Dividing a day's totals by a guessed turn count produced three different "tokens per turn" figures, all wrong. Measure one turn in a window with `SyncJobs` empty, and split the purpose before building any per-surface budget.
- **Another session may be driving the app while you probe.** During the panel a rating and feed builds appeared mid-probe; `UserRatings.Source = Reel` and `SyncJobs.TriggerReason = 'in-app rating'` identified a real second client (the founder's parallel session). Attribute DB writes by those columns, not by timing.
- **`deploy/portainer-stack.yml` is the deploy file the checklist names, and its nginx block rewrites `/api/…` to `/…`** (`proxy_pass` with a trailing-slash URI). Proven with `nginx:alpine` and an echo socket. `docker-compose.prod.yml` and `nginx/nginx.conf` are correct. Fix it before the first deploy or nothing answers.
- **`Tests/IntegrationTests/ReelApiFactory.cs` is the HTTP harness; use it, never a bare `WebApplicationFactory<Program>`.** It blanks every provider key in a static constructor (`DotEnv.Load()` never overrides a set variable), forces `TestHelpers:ModelStubMode`, swaps `IEmbeddingProvider` for the shared stub in `Tests/Fakes/`, removes all ten hosted services, points DI at the `PostgresFixture` DB, and refuses to boot if a live credential is in configuration. Ledger assertions read `IPendingApiUsage.PendingToday` — `ApiUsageRecorder.FlushAsync` is `internal`.
- **CI's integration job filters `FullyQualifiedName~IntegrationTests`.** A DB-backed test anywhere else silently never runs in CI and reports green in the unit job. Every new DB test lives under `Tests/IntegrationTests/`.
- **Every `dotnet` command in `~/src` needs `MSBuildEnableWorkloadResolver=false`** (workload set 10.0.301.1 has missing manifests → MSB4014/MSB4242). `fa.reel.slnx` is at the repo root and is the path `dotnet format` takes. `dotnet format --verify-no-changes` ~25 s, build ~4 s warm, unit ~8 s, integration 45–110 s, vitest ~1 s, full Playwright ~2.5 min.
- **`dotnet run` ignores `ASPNETCORE_URLS`** — `launchSettings.json` pins 5054, the founder's live port. A stack from a worktree must pass `--no-launch-profile --urls http://127.0.0.1:<port>` AND override `ConnectionStrings__Postgres` to a copy database; the headed-round recipe is `.tmp/run-w9.sh` (`pg_dump reel → reel_test_w9`, outbox truncated, pending jobs deleted, every `Background__*` off, API 5069, Vite 5189). **Leave `Background__*` on and the slot processes the copy DB's job queue against the real providers** — the 2026-09-11 QA walk spent ~800 `extract-attributes` calls that way. `/health` is not proxied by Vite. Scripting Chromium directly hits a Playwright browser-version mismatch — `npx playwright install chromium` in the worktree first.
- **`LiveSearchExpansionTests`' semantic-arm pair is an ORDER flake** (~1 run in 4 in the full suite, always green alone and in a class-only run) — shared HNSW index across collections, upstream. Classify by re-running the class alone before touching anything. `BuildFeedNeverEmptyTests.Rating_a_hero_title_vacates_only_its_slot…` is red on `main` deterministically (Programme 2), not a chat regression.
- **React StrictMode mounts, unmounts and remounts every effect, and refs survive the remount.** A mount guard created inside the effect body therefore exists twice: the first instance's deferred abort fires after the second has "mounted", cancelling the request the page itself just sent — and an abort the reducer treats as benign leaves the UI at "Thinking…" forever. Hold one guard per hook instance in a ref and name every deliberate abort; anything unclaimed is an error. Found by instrumenting, not reasoning (2026-09-11 QA walk).
- **A cached LLM interpretation is a function of everything the prompt was given.** `InterpretKey` keyed on the question alone served one thread's history-shaped intent to a fresh thread, byte-identical reply included. Every cache key in front of a prompt carries a digest of each input (history, shown set, standing filters, model, prompt version); "no history" is its own key.
- **Only the request pipeline could close a `SearchTurn`, so an API death mid-stream left it `Pending` forever and the conversation answered 409 to every retry.** `PendingTurnReconciliation` runs at boot (before `app.Run()`, not as a hosted service — those start after the listener) and a three-minute stale rule closes the rest at the gate. Any new "in flight" row needs the same two mechanisms.
- **RTK Query's `data` is the last result the hook saw and survives `skip`** — a deleted thread's transcript came straight back after `+ New` until the resume effect was gated on the same condition as the query.
- **`TenancyModelTests` hard-codes the table count** (45 as of `AskReelTurnModel`). Any new entity bumps it in the same commit as its migration; two branches each adding a table will both bump it and the integrator sums them.

## Model and scoring
- **Verify a failure by observable behaviour — logs, HTTP codes — never by config inspection** (a 2026-08-07 "embeddings broken" diagnosis read one env var, missed the key fallback chain, and steered a whole QA pass at a non-bug).
- **A calibrator fit on pairs with no rank signal is a constant.** Isotonic PAV over ρ≈0 pairs maps everything to the mean — which is honest and useless. Policy since 2026-09-09: bias-shift unless ρ ≥ 0.2 (`CALIBRATOR_MODE`). Also de-mean per artifact: pooling pairs across artifacts whose score levels swing ±1 between retrains blurs the map.
- **The residual head auto-resets on load, not on write.** After a version bump the `OnlineModelStates` row keeps showing the *old* AlgorithmVersion, bias and update count until the next observe, while the served head is already the zero state. Never read that row as the live head.

## Retrieval and pgvector
- **A filtered HNSW search silently returns a FRACTION of the rows it asks for, and the LINQ cannot save you.** An HNSW index scan collects at most `hnsw.ef_search` (default 40) graph candidates and the query's own `WHERE` is applied to that window AFTERWARDS; at pgvector's `hnsw.iterative_scan = off` the scan then stops. So `ORDER BY embedding <=> q LIMIT 40` filtered by eligibility returns *the eligible members of the 40 nearest titles overall*, not the 40 nearest eligible ones — and Reel's eligibility rule removes exactly what a heavy watcher's catalogue is made of, so the arm starves further the more the product is used. **Writing the eligibility predicate "before" the ordering does nothing** — Postgres pushes `ORDER BY … LIMIT` into the index either way; only the planner decides, which is why the symptom is intermittent at fixture scale and permanent at catalogue scale. Measured on 2026-09-10: Ask Reel's semantic arm asked for 40 out of a 20-row eligible set and got 10; a controlled 600-vector probe returned 13 of 40 with the default and 40 of 40 with `strict_order`. Fixed by `HnswFilteredSearchInterceptor`, which sets `hnsw.iterative_scan = 'strict_order'` on every connection from `ReelDbContext.OnConfiguring`. A query with a second `ORDER BY` key (`CandidateRetriever.AnnPullAsync`'s `ThenBy(TitleId)`) usually escapes by making the planner sort — luck, not a guarantee.
- **Never seed `TitleEmbeddings` in the `postgres` collection without inheriting `EmbeddedCatalogTestBase`.** The vectors share one HNSW index, so a fixture's leftovers change which rows an unrelated account's search ever gets to filter — eligibility isolation (a synthetic genre, a reserved dimension block, a non-English language) cannot reach it, because the interference is inside the index. Three fixtures each patched their own half of this before it was written down and `LiveSearchExpansionTests` broke again the moment a fourth embedded fixture landed. `Harness/EmbeddedFixtureIsolationTests` fails the build on a class that skips the base.

## Data and integrations
- **TMDB's TV genre taxonomy has NO horror genre** — American Horror Story arrives as drama/mystery/sci-fi. Anything matching genre terms against `Title.Genres` alone is blind to TV horror; `Subgenres`/`Keywords` carry the truth. The same blind spot applies to any genre-driven feature for TV.
- **Trakt paginated the watched endpoints and changed the `extended` defaults after 2026-06-30** ([trakt-api#775](https://github.com/trakt/trakt-api/discussions/775)). It broke ingest silently: `sync/watched/movies|shows` returned 200 OK with only the first 100 items and no seasons, while ratings came through in full — which is what made it look like a display bug. Fixed by walking `X-Pagination-Page-Count` and requesting `extended=progress` on shows. Two traps: **`extended=full` is now ignored**, and **`extended=progress` is capped at 100 per page** while other watched calls allow 250.

## Front end, search and the stack
- **The dockerized stack must be served on 5173, not the compose default 8090** — the Trakt app registration's only redirect URI is `http://localhost:5173/auth/trakt/callback`, and the registration, not the app, is authoritative. Moving the stack to another port silently breaks sign-in: the OAuth round-trip dead-ends after consent. When the docker gateway owns 5173, do not also start `npm run dev`.
- **The local stack uses `restart: always`; `unless-stopped` silently leaves it dead after Docker Desktop is quit** — it declines to restart a container that was stopped, even when the daemon restarts. **Do not "harmonize" it back to match the prod files:** `docker-compose.prod.yml` and `deploy/portainer-stack.yml` keep `unless-stopped` deliberately, because on the Portainer host an operator's stop should stick.
- **A dead stack still renders the app** — the frontend is a PWA with a precaching service worker, so the cached shell loads normally and the only symptom of a dead backend is the sign-in error on `Landing.tsx`. Confirm something is serving (`curl -s http://localhost:5173/health` must return `{"status":"ok"}`; `000` means the stack is down, not that Trakt is broken) before debugging OAuth.
- **Ask Reel has TWO prompts, and the live one is `OpenRouterSearchAgent.InterpretSystemPrompt`** — not `OpenRouterSearchInterpreter.SystemPrompt`, which is only the fallback. A whole session was lost adding `MaxYear` everywhere except the agent prompt. **Whenever a field is added to `SearchIntent`, update BOTH prompts and verify against the running stack.**
- **A negation can only remove something if it shapes DISCOVERY.** Three things hold together and must not be undone piecemeal: exclusions ride on TMDB `without_genres`/`without_keywords`; the pool is partitioned clean/contradicting *before* the cut, with contradicting titles kept only as a reserve so a negation can never empty the screen; and the ranking query vector is built from the interpreted POSITIVE signal, never the raw sentence — an embedding model has no notion of "not", so embedding "horror but no ghosts" pulls the vector *toward* ghosts. The heuristic tokenizer's clause boundaries are load-bearing for the same reason; do not "simplify" them away.
- **A UI filter the server never sees will empty the screen.** `mediaTypes` rides on the `/api/search/ask` request and narrows discovery; the `done` reason derives from `final.Count` so the footer can never describe a result set the user cannot see; discovery widens through `Relax()` levels until `MinResults` (12), so an empty answer is treated as "we didn't look hard enough", not a verdict.
- **Three ways `/search` scored CLS, and only one of them showed up on a fast machine (2026-09-11, `ci/cls-flake`).** (1) **A placeholder keyed by its position among the placeholders shuffles.** The grid reserve was eight `CardSkeleton`s keyed `slot-0…slot-7`; a card arriving at the head left seven keyed `slot-0…slot-6`, so React kept the same seven DOM nodes and slid every one forward by a cell — 180 px sideways, 305 px for the one that crossed a row, four times over four painted frames. A fast machine coalesces the batch into one layout pass and scores **nothing**; a loaded runner paints each card and scores **up to 0.47**, which is why one CI run read 0.198 and the next 0.423 on the same commit. Key the CELL (`slot-${visible.length + i}`); any reserve rendered as trailing siblings of the real items has this bug unless its keys are absolute. (2) **Animating `left`/`top` bills CLS every frame and bills MORE as the machine slows** — `fa-progress-slide` relayouts its sweep per frame, and dropped frames make each jump bigger; `transform: translateX` is composited, scores nothing, looks identical. (3) **A transient block above the grid cannot just unmount** — the progress banner leaving flow at `done` pulled the grid up 98 px (78 px plus `space-y-5`), 0.0995 on every turn and the one a reader feels. It now sits in a fixed-height slot that hands its box to the answer's provenance line. Reserving a box and leaving it empty trades a jump for a hole; the box has to be given to whatever the next state has to say.
- **Never invalidate the `Feed` RTK tag from a per-title reaction.** Home keys every infinite row on the snapshot's `generatedAt`, so a refetch remounts the rows and discards the pages the user scrolled — acting on one card used to reset the whole list mid-triage. Reactions prune via `removedTitlesSlice` only; a fresher snapshot is *held* and surfaced as "New picks ready"; `useInfiniteRow` tops up below 6 visible cards.
- Only `smoke.spec.ts` gates CI's e2e job. Images publish under `latest` only. The compose comment still says `vector(384)` while the provider emits 1536 dims. Tailwind is **v3.4.10**.
- **Never leave the compose `backend` container running beside the dev loop.** Both connect to the same Postgres and share the `SyncJobs` queue (`FOR UPDATE SKIP LOCKED`), so a month-old image silently claimed Train/BuildFeed jobs on 2026-09-10: it kept writing schema-3 artifacts (v13–v17), the new binary's schema sweep kept superseding them (a retrain loop), and `FeedBuildStats`/`ExposureEvents` stayed at zero while snapshots appeared. `docker compose stop backend frontend gateway` — only `postgres` stays up. A build that cannot read the Active artifact now logs at Error and writes a `Skipped` stat row naming both schema versions.
