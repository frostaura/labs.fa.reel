# Gotchas

- **Ask Reel: a UI filter that the server never sees will empty the screen.** Fixed 2026-07-24. The movie/TV toggle was applied only to the rendered cards, so a turn that legitimately returned 8 shows rendered "No matches" under "Movies" — while the footer still read "Pulled 50…; 8 unseen", because that string was built from the pre-ranking counts and never referenced what was actually returned. Three rules now hold and should not be quietly undone: (a) `mediaTypes` rides on the `/api/search/ask` request and narrows *discovery*, so results arrive already matching; (b) the `done` reason is derived from `final.Count`, so the footer can never describe a result set the user cannot see; (c) discovery widens through `Relax()` levels until `MinResults` (12), then falls back to the account's own eligible catalogue by popularity — an empty answer is treated as "we didn't look hard enough", not a verdict.
- **Negation was inverted in search intent.** The interpreter had no notion of "not"/"less"/"don't want", so rejected terms landed in `Genres`/`Keywords` — which are TMDB *fetch* signals — and Ask Reel actively went looking for what the user had just refused ("I don't want ghosts" fetched ghost stories). `SearchIntent` now carries `ExcludeGenres`/`ExcludeKeywords`, populated by both the LLM prompt and the heuristic tokenizer, applied as a discovery exclusion plus a bounded ranking demerit — never a hard cull, so a negation can reorder but can never empty. Regression coverage: `FrostAura.Reel.Tests/Search/SearchNegationTests.cs`.
- **Never invalidate the `Feed` RTK tag from a per-title reaction.** Home keys every infinite row on the snapshot's `generatedAt`, so refetching the feed remounts the rows and discards the pages the user scrolled. Because each reaction also queues a server `BuildFeed`, rating/saving/dismissing one card used to reset the whole list mid-triage — queueing three titles from one row was impossible. Fixed 2026-07-24: reactions now prune via the local `removedTitlesSlice` only, a fresher snapshot is *held* (`lib/feedSeed.ts` — `resolveSeedKey` returns null unless it is the first snapshot or the user pressed refresh) and surfaced as a "New picks ready" control, and `useInfiniteRow` tops up below 6 visible cards so acting on a card pulls the next one in. Continue-watching got its own `ContinueWatching` tag so drop/undrop can refresh that rail alone. Regression coverage: `src/frontend/src/lib/feedSeed.test.ts`.
- **Trakt paginated the watched endpoints and changed the `extended` defaults, enforced after 2026-06-30** ([trakt/trakt-api#775](https://github.com/trakt/trakt-api/discussions/775)). This broke ingest silently on 2026-07-24 — Reel's client predated the change (last touched 2026-06-19), so `sync/watched/movies|shows` returned **200 OK with only the first 100 items** and no seasons. The founder's library ingested as exactly 100 movies / 100 shows / **0 episodes** while ratings (3,605, unaffected) came through in full, which is what made it look like a display bug rather than an ingest bug. Fixed in `TraktClient` by walking pages via the `X-Pagination-Page-Count` header and requesting `extended=progress` on shows. Two traps to keep in mind: **`extended=full` is now ignored** (item metadata comes from TMDB enrichment anyway, which is why nothing else regressed), and **`extended=progress` is capped at 100 per page** while other watched calls allow 250. Regression coverage: `FrostAura.Reel.Tests/Ingestion/TraktWatchedPaginationTests.cs`.
- **The dockerized stack must be served on 5173, not the compose default 8090** — the Trakt app registration's only redirect URI is `http://localhost:5173/auth/trakt/callback`, and it is the registration, not the app, that is authoritative. `.env` therefore sets `GATEWAY_PORT=5173` (plus matching `APP_PUBLIC_URL` / `CORS_ALLOWED_ORIGINS`). 5173 is nominally the Vite dev port; when running the docker stack the nginx gateway owns it, so do not also start `npm run dev`. Moving the stack to another port silently breaks sign-in — the OAuth round-trip dead-ends after consent.
- **The local stack uses `restart: always`; `unless-stopped` silently leaves it dead after Docker Desktop is quit.** Diagnosed 2026-08-07 from a "Couldn't reach the sign-in service" report. All four containers exited 0 at the same instant on 2026-07-30 (Docker Desktop quit; the Mac itself had not rebooted — 13 days' uptime), and when Docker Desktop was reopened a week later the stack did **not** come back. That is `unless-stopped` behaving exactly as documented: it declines to restart a container that was stopped, *even when the daemon restarts*. `always` is the policy that restarts with the daemon, so `docker-compose.yml` now uses it on all four services. **Do not "harmonize" it back to `unless-stopped` to match the prod files** — `docker-compose.prod.yml` and `deploy/portainer-stack.yml` keep `unless-stopped` deliberately, because on the Portainer host an operator's stop should stick. The compose `depends_on: condition: service_healthy` ordering does *not* apply to policy-driven restarts, but the stack still converges: each service crash-loops until its dependency answers. Verified by restarting Docker Desktop and watching all four return healthy with no `docker compose up`.
- **A dead stack still renders the app — the frontend is a PWA with a precaching service worker** (`vite-plugin-pwa`, `generateSW`, 6 precached entries). With nothing listening on 5173 the cached shell loads normally, so the *only* symptom of a completely dead backend is the sign-in error on `Landing.tsx`. Before debugging OAuth, confirm something is actually serving: `curl -s http://localhost:5173/health` must return `{"status":"ok"}`. A `000` means the stack is down, not that Trakt is broken. A hard-reload (Cmd-Shift-R) also clears the stale shell.
- **The pre-provisioned Trakt tokens in `.env` are stale/revoked** (verified 2026-07-24: `POST /api/auth/dev/link` → Trakt `invalid_grant` "session not found"). The dev QA helper is dead until one real OAuth sign-in re-links the dev profile.
- **Trakt's Cloudflare blocks the Claude Code browser pane** ("Sorry, you have been blocked" on the authorize page — the Electron UA trips bot protection). OAuth sign-in has to be done in a normal browser; the pane can be used for everything after a session cookie exists.
- **`.env` holds live credentials inside iCloud Drive** — Trakt client secret, TMDB token, OpenRouter key, JWT signing secret and real Trakt access/refresh tokens. Correctly gitignored, but continuously synced to Apple's cloud and every device on the account. Rotate before public launch, and decide deliberately about keeping live secrets here at all.
- **The repo's `.git` carries stale lock files that this workspace cannot delete** (`Operation not permitted` on the iCloud mount). Any agent that cannot commit here should check `.git/*.lock` first — see the division `MEMORY.md`; the founder clears them with one `rm` on the Mac.
- Local Postgres publishes on **5433**, not 5432.
- iCloud filename-conflict duplicates keep appearing under `src/backend/**/bin/` and `obj/` (`... 2.dll`, `... 2.pdb`) — a direct symptom of building inside iCloud Drive. Build output only; harmless but noisy.
- **`EMBEDDINGS_API_KEY` is blank in the running backend — embeddings are almost certainly 401ing.** Verified 2026-08-07 by `docker exec fareel-backend-1 printenv EMBEDDINGS_API_KEY` (empty) against `OPENROUTER_API_KEY` (set). `.env` still carries only the vestigial `OPENAI_API_KEY=` (also empty), but compose passes `EMBEDDINGS_API_KEY`, so nothing reaches the provider. Because `EMBEDDINGS_BASE_URL` points at OpenRouter by design, the fix is to make the two share a key — either add `EMBEDDINGS_API_KEY` to `.env` or default it to `${OPENROUTER_API_KEY}` in compose. **Not yet fixed** — found while diagnosing an unrelated sign-in failure and deliberately left alone rather than folded into that change. Semantic/vector search quality should be treated as unproven until this is closed.
- Of six Playwright e2e specs only `smoke.spec.ts` gates CI. Images publish under `latest` only — no semver.
- The compose comment still says `vector(384)` while the configured provider emits 1536 dims.
- Tailwind is **v3.4.10**, not v4.
